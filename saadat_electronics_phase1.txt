# Implementation Plan - Sadaat Electronics & A.K. Traders CRM

Building a production-ready Laravel + Blade/Tailwind CRM for **SADAAT ELECTRONICS** (retail sales & appliance service) and **A.K. TRADERS** (wholesale/dealer business), featuring a dark modern aesthetic inspired by the provided CRM reference screenshots.

## User Review Required

> [!IMPORTANT]
> **Key Architecture & Security Constraints Enforced:**
> 1. **Strictly 2 Roles Only**: `Admin` and `Technician`. No extraneous roles.
> 2. **Technician Isolation**: Technicians cannot access admin management screens, cannot view or modify other technicians' jobs, cannot assign technicians, and cannot close complaints. All restricted queries are scoped at the policy/repository/controller query level, preventing URL manipulation.
> 3. **Verification Workflow**: When a technician completes a job, records parts, and logs cash received, the complaint status becomes `Completed — Awaiting Admin Verification`. Admin must explicitly review and verify before the complaint can be closed and before customer feedback messages can be dispatched.
> 4. **Accounting & Pricing Integrity**: Profits are calculated dynamically (`Profit = Sale Amount - Actual Purchase Cost`). Cash recorded by technicians is flagged as unverified until verified by Admin.
> 5. **Public API Sanitization**: `POST /api/public/complaints` strictly excludes internal fields (technician assignment, priority override, internal costs, status override).

## Proposed Architecture & Design System

### 1. Visual Design & Theme Matching Reference Screenshots
- **Color Palette**:
  - Background: Dark Navy/Charcoal `#0B131B` (base), `#111C26` (surface/cards), `#1A2836` (borders/inputs)
  - Primary Accent: Bright Cyan/Teal `#06B6D4` / `#14B8A6` / `#2DD4BF`
  - Success/Profit: Emerald Green `#10B981` / `#22C55E`

### 3. Middleware, Policies & Authorization
- **Middleware**:
  - `AdminMiddleware`: Ensures only `auth()->user()->role === 'admin'` can access admin routes.
  - `TechnicianMiddleware`: Ensures only `auth()->user()->role === 'technician'` can access technician routes.
- **Policies**:
  - `ComplaintPolicy`:
    - `view(User $user, Complaint $complaint)`: Admin can view any; Technician can only view if `$complaint->technician_id === $user->id`.
    - `update(User $user, Complaint $complaint)`: Admin can edit everything; Technician can only edit repair notes, parts, cash, and submit for verification if assigned to them and status is not `closed`.
    - `verify(User $user, Complaint $complaint)`: Only Admin.
    - `delete(User $user, Complaint $complaint)`: Only Admin (prevented if related invoices exist).

   - Send `POST /api/public/complaints` with test JSON payload.
   - Verify complaint is created with status `new` and no technician assigned.
